# Mindmap Builder

## Overview
This skill contains best practices for building effective mind maps based on the "Radiant Thinking" model described in "Visualising Domain Ontologies Using Mindmaps to Enhance Requirements Engineering" (Zayed, Kossmann, and Odeh).

## Key Principles and Guidelines

- **Radiant Thinking:** Human brains process information by radiating out from a central point. Mind maps should reflect this cognitive pattern.
- **Centrality:** Every mind map MUST start with a single central topic or concept (often marked as `[ROOT]`) from which all other ideas originate.
- **Hierarchical Structure:** Organize information hierarchically. Move from general, high-level concepts (near the center) to specific details (at the outer branches).
- **Multi-Sensory Elements:** 
  - **Visual Coding:** Use symbols, shapes, or emojis to represent different types of data (e.g., specific shapes for classes vs. properties).
  - **Colors:** Use different colors for different branches to distinguish between themes and improve readability.
- **Infinite Expansion:** Mind maps are infinite; they can constantly branch off into sub-branches and even generate associated "mini mind maps."

## Rules and Best Practices

- **Use Keywords:** Instead of long sentences, use single keywords or short phrases. This keeps the map concise and stimulates rapid associations.
- **Connection and Tracing:** Ensure all elements are graphically linked to show dependencies and relationships. Users should be able to trace knowledge "back and forth" up to the high-level concepts.
- **Simplification:** Use the mind map to simplify complex data (like ontologies or database schemas) into a format easily understood by non-technical stakeholders.

## Specific Steps to Build a Mind Map

When asked to generate or format a mind map, follow these steps:

1. **Establish the Center:** Start in the middle (or the very top of a hierarchy) with a **central topic or concept** that represents the main subject.
2. **Identify BOIs:** Radiate the **Basic Ordering Ideas (BOIs)** out from the central concept. These are the first-level key topics or primary categories.
3. **Apply Color Coding:** If the medium supports it, apply **different colors** for each BOI branch to create clear visual boundaries.
4. **Hierarchical Expansion:** Expand the BOIs by adding **branches and sub-branches**, where each level further defines the one before it.
5. **Incorporate Visuals:** Add **keywords, symbols, drawings, and images** (or emojis if in text format) to the branches to make the information memorable.
6. **Refine and Link:** Continue branching off as ideas occur, ensuring all new nodes are correctly connected to their parent concepts to maintain a clear organizational structure.
